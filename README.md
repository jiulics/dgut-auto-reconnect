# DGUT Auto Reconnect

Windows 上的 DGUT 校园网自动重连助手：后台检测直连联网状态，必要时打开认证入口，由油猴脚本使用**本机离线 OCR**识别四位数字验证码、填写并提交，最后由后台验证是否恢复联网。

> 仅用于本人获授权的校园网账号与设备，并遵守学校网络使用规定。它不绕过账号认证、不增加设备配额、不处理滑块或点选验证码，也不保证所有断网原因都能自动恢复。

## 功能与工作流程

1. Windows 后台串行检测联网状态，连续三轮失败后检查认证入口。
2. 入口可达且没有活跃的新版认证页时，打开默认浏览器。
3. 油猴脚本向本机服务查询联网状态；只有明确掉线时才尝试登录。
4. 如果页面要求验证码，读取**已经显示的图片像素**，交给本机 OCR；仅接受四位 ASCII 数字。
5. 填写真正的验证码字段并触发输入事件，再点击原网页的登录按钮。
6. 后台检测恢复联网后回到监控状态；点击登录本身不视为成功。

附带：跨标签页共享重试限额、重复进程保护、页面心跳、旧脚本冲突检测、代理例外设置与回滚、日志轮转。

## 环境要求

- Windows 10/11，Windows PowerShell 5.1。
- Python 3.10 或以上及 pip；本项目已在 Windows x64 / Python 3.13 环境运行验证。其他版本仍需自行验证依赖兼容性。
- 默认浏览器中安装 Tampermonkey 或兼容的用户脚本管理器，并允许脚本在认证页面运行。
- 首次安装 Python 依赖需要网络；安装完成后 OCR 推理不依赖外网。
- Node.js 仅用于开发测试，日常运行不需要。

模型来自 [ddddocr](https://github.com/sml2h3/ddddocr)，固定主依赖版本为 `1.6.1`。模型及依赖由 pip 安装，不包含在本仓库中；传递依赖未全部锁定，因此不能保证不同日期安装得到完全相同的环境。

## 安装

### 1. 下载项目并建立本地 Python 环境

将项目放到一个可长期保留的文件夹，在该文件夹打开 PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

没有 `py` 命令时，可用已安装的 Python 解释器替代第一条命令中的 `py -3`。确保最终存在 `.venv\Scripts\pythonw.exe`，后台使用它启动本机 OCR 服务。

不要复制其他电脑的 `.venv`。移动项目后如虚拟环境失效，应在新位置重新创建。

### 2. 安装或更新油猴脚本

1. **停用旧版**“DGUT校园网自动认证不准断网2026”。
2. 用文本编辑器打开 [dgut-reconnect.user.js](dgut-reconnect.user.js)，复制全文。
3. 在油猴中新建脚本，或编辑原来的“DGUT 校园网持续认证助手（本地版）”，替换全部内容并保存。版本应为 **2.0.0**。
4. 不要并列安装多个副本。更改本地 `.user.js` 文件不会自动更新浏览器中已安装的副本。
5. 若油猴请求访问 `127.0.0.1`，允许该本机地址。
6. 刷新已有认证页，让旧版残留定时器退出、新版生效。

不要把 `.user.js` 当成 Windows 程序双击运行。脚本必须安装在**默认浏览器实际使用的用户配置**中；后台打开的是系统默认浏览器。

### 3. 按需配置认证域名直连

使用系统 HTTP 代理时，在项目目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\proxy-bypass.ps1
```

只向当前用户的 Windows `ProxyOverride` 增加 `login.dgut.edu.cn`，不关闭代理、不更换代理地址，也不修改订阅；会在本地记录回滚信息。

这是系统 HTTP 代理例外，**不控制 TUN、浏览器代理扩展或其他路由层**。若认证跳转目标仍被代理接管，需要在相应客户端核实 DIRECT 规则。代理软件重写系统例外后，也可能需要重新执行该命令。

### 4. 启动

双击 `start.cmd`。它隐藏启动后台守护，守护再启动本机 OCR 服务。重复启动不会产生多个守护循环。

浏览器需保留可用的认证信息；本项目不读取、保存或代填账号密码。需要首次手动登录、验证码类型变化或账号异常时，仍须人工处理。

**默认没有设置开机自启。重启电脑后需重新运行 `start.cmd`。**

## 日常操作

| 操作 | 方法 |
|---|---|
| 启动后台和 OCR | 双击 `start.cmd` |
| 停止后台和 OCR | 双击 `stop.cmd`，等待正在执行的请求结束 |
| 暂停网页自动认证 | 点击新版控制面板“暂停自动认证” |
| 恢复网页自动认证 | 点击“恢复自动认证” |
| 单次只读联网检测 | `powershell -NoProfile -File .\guardian.ps1 -Once` |

停止后台与暂停网页是两个独立操作。彻底停止自动工作时，执行 `stop.cmd` 并暂停网页脚本，或关闭认证页。停止 OCR 后网页无法继续识别与提交，但仍可能尝试连接本机服务。

后台正常联网时不会不断写事件日志；请通过状态文件的 `Updated` 字段判断检测是否持续运行。

## 日志和运行状态

运行时会在项目目录生成以下文件，它们不应上传到 GitHub：

| 文件 | 内容 |
|---|---|
| `guardian.log` | 启动、停止、打开认证页、后台异常 |
| `ocr.log` | OCR 就绪、识别、提交、旧脚本冲突等事件 |
| `guardian-status.json` | 最近一次联网检测结果 |
| `portal-lease.json` | 新版页面存活期限 |
| `guardian.stop` | 停止标志，重新启动时自动清除 |
| `proxy-bypass-backup.json` | 代理例外的本地回滚记录 |

实时查看日志：

```powershell
Get-Content .\guardian.log -Tail 30 -Wait
# 在另一个 PowerShell 窗口中查看 OCR 事件
Get-Content .\ocr.log -Tail 30 -Wait
```

`Ctrl+C` 只结束日志查看，不停止守护。日志约 1 MB 轮转并保留一个上一份文件。

状态文件字段：

| 字段 | 含义 |
|---|---|
| `Updated` | 最近一次检测完成时间 |
| `PID` | 守护进程编号 |
| `Online` | 直连探测是否通过，不代表代理节点健康 |
| `Failures` | 连续失败次数 |
| `PageActive` | 新版网页心跳是否仍在有效期内 |
| `PortalReachable` | 掉线时认证入口是否可达；联网正常时不检查，因此 `false` 不代表故障 |
| `Action` | `online` 正常；`wait` 等待；`open` 本轮打开了认证入口 |

典型认证事件：

```text
attempt_reserved
ocr_recognized_four_digits   # 只有需要验证码且识别成功时出现
submitted
```

之后还需要确认 `Online=true`。`submitted` 只表示执行了登录点击，不代表服务器接受了账号或验证码。

本机服务健康检查（PowerShell 5.1 兼容）：

```powershell
$client = New-Object System.Net.WebClient
$client.Proxy = $null
$client.Headers['X-DGUT-Client'] = 'local-v2'
try { $client.DownloadString('http://127.0.0.1:18761/health') }
finally { $client.Dispose() }
```

## 时序与重试策略

- 每轮后台检查完成后等待 15 秒；每个网络请求超时 8 秒。请求耗时会增加周期，不是严格每 15 秒一次。
- 使用两个 Microsoft 连通性端点，首个失败后才检查第二个；必须返回预期正文，不跟随重定向。两者同时受阻也可能造成误判。
- 连续三轮失败且认证入口可达、没有活跃新版页面时，打开浏览器。同一次连续掉线的开页冷却为 300 秒；中间恢复联网会重置冷却。
- 新版网页每轮完成后等待 5 秒，并向本机报告存活。心跳期限为 60 秒；关闭页面或后台标签页被浏览器节流后，后台可能再次开页。
- 所有标签页通过同一个本机服务共享限额：滚动 15 分钟内最多 3 次尝试，第二、第三次与前次至少相隔 30、60 秒。识别失败等情况也消耗已预留的额度。
- 网络恢复后重置限额；**本机服务重启也会清空内存限额**，不应靠反复重启增加尝试次数。
- OCR 结果必须为四位数字。识别失败、图片变化、暂停或冲突时停止本次提交；四位数字格式正确并不保证识别内容正确。

## 两个面板与旧脚本冲突

新版以唯一 DOM ID 防止自身重复创建面板。若发现旧面板，会通过旧版暂停按钮停止其定时循环并隐藏旧面板，同时**拒绝新版提交**并提示处理冲突。

但旧版还有不受暂停状态控制的加载时点击，所以完整处理步骤是：

1. 在油猴中停用旧版脚本和重复副本。
2. 用 2.0.0 覆盖之前的本地版副本，而不是额外安装一份。
3. 刷新认证页，清除旧页面中仍然存在的定时器。

仅删除旧面板并不能停止旧代码。历史日志中的 `legacy_conflict` 也不会因处理完成而自动删除，应结合时间判断是否仍在发生。

## 常见问题

### 页面提示无法连接本地 OCR

确认已运行 `start.cmd`，`.venv` 安装完整，健康检查通过，并且油猴允许连接 `127.0.0.1`。端口 `18761` 被其他程序占用时查看 `ocr.log`；不要盲目结束不认识的进程。

### 输入框里有文字却提示验证码为空

该认证页同时有真实字段 `validCode` 和提示字段 `validCode_tip`。新版写入真实字段并触发事件。若学校页面结构已变化，需要重新适配，不能仅凭截图判断提交内容。

### 验证码仍识别失败

当前仅适配四位数字。图片不可读、跨域 canvas 限制、图片未加载、验证码过期、滑块或点选验证都不会强行提交。查看 `ocr.log`，必要时暂停自动认证并手动登录。

### 日志没新内容，是否已经停止？

正常状态下事件日志较少；查看 `guardian-status.json` 的更新时间和进程是否仍存在。网页心跳持续但账号无法认证时，页面会保持限频重试，不会无限高频提交。

### 如何撤销代理例外？

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\proxy-bypass.ps1 -Restore
```

根据本机备份记录移除此次添加的认证域名，保留其他例外。不要把其他电脑的备份文件复制过来回滚。

## 隐私与安全边界

- OCR 接收验证码图片像素，不接收账号、密码、Cookie、认证 URL 或整页截图；图片和识别结果不写入日志。
- 服务只监听 `127.0.0.1`，检查 Host、Origin 和自定义请求头，并限制图片尺寸、请求大小及识别频率。
- 自定义请求头不是身份认证密钥；同机进程仍可调用该服务。不要将端口转发到公网或局域网。
- 原网页提交登录时仍会按学校网站原有逻辑发送认证信息；本项目不改变网站本身的传输安全性。
- 后台直连请求绕过系统 HTTP 代理，但不能绕过 TUN 或操作系统路由。关闭电脑、休眠、物理断线、学校服务器故障时不能保证联网。
- 运行文件、个人代理备份、截图、历史脚本和虚拟环境均由 `.gitignore` 排除。

## 开发与验证

在项目根目录运行：

```powershell
powershell -NoProfile -File .\tests.ps1
node --test .\userscript.test.cjs .\ocr-userscript.test.cjs
.\.venv\Scripts\python.exe -m unittest discover -s . -p test_ocr_service.py
node --check .\dgut-reconnect.user.js
```

已有验证：15 项 PowerShell 断言、18 项 JavaScript 测试、5 项 Python 测试；覆盖掉线状态机、限额、暂停、图片变化、字段填写、旧版冲突和重复注入等。另已完成本机 HTTP 健康检查、非预期来源拒绝测试，以及一张用户提供的验证码截图识别测试。

实际运行日志已出现新版提交认证事件，随后检查到联网正常。但尚未完成可控的“掉线 → 出现真实验证码 → 自动识别提交 → 联网恢复”端到端测试；单张截图识别正确不代表总体准确率。不要据此承诺全天候无故障或无人值守必然成功。
